# P9.14 Experimental C# Change Proposal Review

Date: 2026-07-13

## Decision

P9.14 passes the bounded proposal-and-delta implementation gate. It makes the project Workbench capable of showing the graph delta and code diffs that were intentionally unavailable in P9.13, while preserving a strict non-applied authority boundary.

## Real Adoption Candidate

The WindowsUtility SimpleInfo candidate is grounded in current source behavior:

- `CsdBrowseService.BrowseFolder` returns an empty list when folder selection is cancelled.
- `SimpleInfoViewModel.BrowseFolder` forwards that value directly to `LoadDocuments`.
- `LoadDocuments` clears the current document list before handling an empty list.
- the existing file-browse path already uses `null` to distinguish cancellation.

The proposal changes only the relevant interface method, service implementation, and view-model consumer. It is not applied.

## Delivered Workbench Data

- one non-applied proposal node
- seven graph-delta steps: three changed code facts, one added verification node, and three code-diff review steps
- three digest-backed code-diff fragments
- a delta-step list that focuses the corresponding graph node
- code-fact inspector content that includes the associated proposal diff
- proposal verification and evidence requirements, both marked required rather than collected

## Verification

- the P9.14 project workspace, emitted projection, manifest, and HTML validate deterministically
- inline Workbench JavaScript passes `node --check`
- proposal negative probes reject wrong role, applied status, unknown changed facts, stale diff digest, authority promotion, invalid diff content, unresolved delta edge, and missing verification requirements
- P9.13 project-state negative probes still pass after the proposal extension
- the WindowsUtility repository was only read; its existing user changes in `App.xaml`, `AppThemePalettes.cs`, and `MainWindow.xaml` were not touched

## Remaining Boundary

The proposal is not accepted, applied, built, or manually verified. The next product workflow must provide a reviewed mapping/decision boundary and an evidence execution path before it can move from `review-required` to source application. Browser interaction evidence for the static local page also remains a separate visual quality gate.
