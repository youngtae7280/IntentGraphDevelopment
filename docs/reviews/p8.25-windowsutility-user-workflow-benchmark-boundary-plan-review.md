Work item: P8.25 WindowsUtility User Workflow Benchmark Boundary Plan

Decision: pass; a human/coordinator workflow benchmark must be requested before productization or broader adoption claims.

## Scope

P8.25 defines the first user-facing workflow benchmark for the WindowsUtility shell/workspace adoption loop.

This slice is plan/report-only. It does not run the benchmark, collect user responses, mutate WindowsUtility, apply proposals, grant AI authority, grant hardware authority, or claim productization readiness.

## Benchmark Goal

Determine whether the current IntentGraph workflow helps a reviewer understand:

- what was mapped;
- what was proposed;
- what evidence was collected;
- which safety boundaries remain false;
- whether the target repository stayed unchanged;
- what the next decision should be.

## Participant And Mode

Participant:

- user/coordinator

Mode:

- local review of generated artifacts
- no target source edits
- no hardware actions
- no proposal application

## Benchmark Materials

The benchmark should present:

- workbench HTML: `generated/windowsutility/workbench/p8.21-shell-workspace-evidence-workbench.html`
- workbench projection: `generated/windowsutility/workbench/p8.21-shell-workspace-evidence-workbench-projection.json`
- usability dry-run report: `generated/windowsutility/workbench/p8.24-shell-workspace-workbench-usability-dry-run-report.json`
- accepted mapping: `generated/windowsutility/p8.9-shell-workspace-accepted-mapping.json`
- screenshot evidence: `generated/windowsutility/p8.19-shell-workspace-sandboxed-window.png`

## User Tasks

Ask the participant to answer:

1. What mapping has been accepted?
2. What code surface does it cover?
3. What evidence proves build/UI/screenshot status?
4. Was the proposal applied?
5. Did the original WindowsUtility repo change?
6. Which authority boundaries are still false?
7. Is this enough to proceed toward productization?
8. What is confusing or missing?

## Metrics

Record:

- answer correctness
- user confidence
- time or rough duration
- number of raw files opened
- whether screenshot was found
- whether authority false flags were found
- confusion notes
- proceed/pause/pivot recommendation

## Pass Criteria

The benchmark may pass only if:

| Criterion | Required result |
|---|---|
| user can identify accepted mapping | Pass |
| user can identify proposal non-applied state | Pass |
| user can identify build/UI/screenshot evidence | Pass |
| user can identify target unchanged state | Pass |
| user can identify authority false flags | Pass |
| user reports no blocking confusion | Pass |
| user does not infer productization readiness | Pass |

## Stop Conditions

Stop productization planning if:

- the user believes the workbench implies source edits or productization authority.
- the user cannot find evidence or safety boundaries.
- the workbench causes more confusion than raw artifacts.
- the user says the current workflow is not useful enough to continue.
