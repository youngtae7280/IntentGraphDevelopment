# P9.32 Headless Browser Runtime Regression Review

Status: pass for the bounded real-browser regression boundary.

## Decision

P9.32 passes. The WindowsUtility project Workbench now carries a query-activated,
read-only runtime probe and a standard-library runner that launches an installed Edge
or Chrome process. The probe verifies the actual rendered graph instead of inferring
visual behavior from HTML markers alone.

## Observed Browser Result

The P9.32 static Workbench was served on an ephemeral loopback port and rendered by
Microsoft Edge `150.0.4078.65` in headless mode at 1440 by 1000 pixels. The report also
binds the exact `msedge.exe` bytes by SHA-256.

- 8,208 nodes and 8,023 relations were loaded in one Cytoscape graph instance
- overview canvases contained 2,652 sampled opaque pixels
- the cached material canvas contained 435 sampled opaque pixels
- logical zoom reached 100, renderer zoom remained 24, and effective geometry zoom was 100
- virtual geometry scale was 4.1667
- the selected relation endpoint distance changed from 51.7457 to 215.6070, an
  observed model-space ratio of 4.1667 rather than a display-only zoom claim
- the selected relation rendered at 0.065 pixels and 0.34 opacity
- active material was `cached-spectral-titanium-v2` with 32 bounded cached sprites
- the selected edge inspector exposed its source and target
- browser runtime error collection was empty
- the PNG screenshot was valid at 1440 by 1000, 277,452 bytes, with 63 sampled color
  buckets and a luminance range of 243

The screenshot is retained outside the immutable Workbench input at
`generated/roadmap/p9.32-headless-browser-runtime-screenshot.png`.

## Implementation Boundary

- normal Workbench behavior is unchanged unless `intentGraphRuntimeProbe=1` is present
- the page probe selects one existing relation, renders the selection inspector, moves
  to logical 100x, samples its graph canvases, and publishes one JSON observation
- the Python runner uses one browser process with browser-native `--headless=new`,
  `--dump-dom`, and screenshot capture; the structured observation and PNG therefore
  describe the same run
- input HTML, projection, manifest, and validation digests plus the exact browser
  executable digest and Windows file version are recorded in the report
- report and screenshot paths must differ and both must remain outside the input Workbench
- no Selenium, Playwright, Puppeteer, or other automation dependency is added
- the runner serves only the supplied static directory over loopback
- browser evidence is observational evidence, not graph, source, or semantic authority

## Fail-Closed Evidence

The repeatable validator harness passed 18 of 18 probes. It rejected wrong node and
edge counts, a failed or missing required page check, blank overview or maximum-zoom graph/material
canvases, unapplied endpoint geometry scaling, wrong effective zoom, an oversized
selected edge, the wrong material profile, an empty selection inspector, a runtime
script error, an invalid screenshot, input-output overwrite, and output collisions.

## Regression Evidence

- static Workbench emission and validation: pass
- repeated emission: six files byte-identical
- inline JavaScript parse with `node --check`: pass
- loopback interactive server smoke: 30/30 pass
- project workspace negative probes: 8/8 pass
- headless Edge runtime observation: pass
- repeated headless Edge structured runtime observation: exact match
- both PNG captures independently passed dimensions, nonblank, luminance, color, and
  chromatic pixel checks; their hashes are intentionally not a golden-image contract
- browser validator and output-guard negative probes: 18/18 pass
- Python compile check: pass
- graph, source, snapshot, target repository, and authority mutation: false

## Known Limits

- the screenshot digest is environment evidence, not a cross-browser golden-image contract
- the harness currently requires an installed Edge or Chrome executable
- the browser probe validates nonblank material and screen-scale contracts; it does not
  score subjective aesthetics or replace human visual review

## Follow-up

The manual-only rendering evidence gap is closed. The next product slice should return
to the highest-value daily-use bottleneck, especially a cohesive installation and
launch workflow for the local review kit, rather than adding another renderer-only
refinement without new user evidence.
