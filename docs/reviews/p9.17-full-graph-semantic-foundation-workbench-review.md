# P9.17 Full-Graph Semantic Foundation Workbench Review

Date: 2026-07-13

## Decision

P9.17 passes the bounded full-graph and semantic-foundation gate.

The earlier semantic-first default was an overcorrection: it prevented raw code from overwhelming the screen by withholding the full graph. The corrected design keeps every projected record in the initial graph while using deterministic source-community placement and progressive visual detail.

## Evidence

The WindowsUtility projection contains:

- 8,188 nodes and 8,040 relations
- all 8,188 node identifiers in the default full-graph view
- 8,137 extracted code facts and 17 derived code capsules
- 18 declared semantic-foundation nodes: 4 source documents, 3 goals, 8 capabilities, 2 constraints, and 1 verification requirement
- one explicit work/Intent/mapping/proposal chain for the CSD browse-cancel request

The browser smoke confirms the local shell loads before the projection and that a full-graph to semantic-overview switch and return use the existing graph instance. In the checked local run, the semantic lens changed in approximately 420 ms and returning to the 8,188-node full lens in approximately 635 ms.

## Safety and Truthfulness

- Intent Units are still created only from explicit work requests.
- The foundation records declared project meaning from supplied artifacts; it does not claim automatic requirement understanding.
- Foundation negative probes reject wrong role, automatic Intent creation, unknown code capsules, physical path persistence, unknown document references, and unreviewed replacement.
- Every negative failure leaves local project state unchanged.
- No WindowsUtility source file was changed.

## Remaining Product Gap

P9.17 is a local single-user Workbench. It does not yet provide reviewed foundation replacement, automatic semantic extraction with confidence review, interactive proposal authoring, controlled evidence execution, editor integration, multi-user coordination, or distributable packaging.
