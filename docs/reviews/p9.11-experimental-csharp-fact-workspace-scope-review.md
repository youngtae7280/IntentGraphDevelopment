# P9.11 Experimental C# Fact Workspace Scope Review

Date: 2026-07-13

Decision: authorize `P9.12 Experimental C# Fact-Only Workbench`; retain the experimental syntax-only and fact-only boundaries.

## Evidence Reviewed

- P9.10 validates a copied C# snapshot with path-free provenance, 206 source files, 8,137 code facts, and 7,931 syntax relations for the WindowsUtility reproduction.
- The C# facts contain relative code pointers, source digests, source ranges, confidence, and extractor boundaries but no source text or resolved semantic calls.
- B1's workbench requires an Intent mapping and non-applied proposal. P8.60's approval workbench requires deltas, diffs, evidence, and authority links. Neither is an honest contract for a fact-only C# workspace.
- Existing local Cytoscape-based workbenches demonstrate useful graph interaction patterns, but their approval/change assumptions must not be copied into a fact-only surface.

## P9.12 Decision

P9.12 may render only validated P9.10 facts as a local static HTML inspection surface. It must visually distinguish three categories:

```text
recorded: snapshot receipt, C# facts, syntax relations, extraction/validation results
not recorded: mapping, proposal, delta, diff, verification, evidence, acceptance authority, history
not claimed: semantic calls, project evaluation, target execution, mutation, product support
```

The workbench must support graph navigation and source-pointer inspection. It must not pretend that absent semantic/change artifacts are negative project facts or completed checks.

## Required Gate Conditions

P9.12 must satisfy the P9.11 product contract and V431. It must read a P9.10 workspace without changing it, write to a new separate output directory, validate its local bundled runtime and HTML behavior, provide repeatable negative probes, and capture browser interaction evidence from a fact-only fixture plus a real WindowsUtility snapshot when available.

## Deferred Decisions

- whether C# fact quality is sufficient for Intent mapping
- how a natural-language request becomes an Intent hypothesis
- semantic call resolution and project-system evaluation
- portable C# dependency distribution
- a generic multi-language or multi-profile workbench

## Recommendation

Proceed with P9.12. A passing surface will make current project structure and the absence of higher-level IGD work visible; it will not itself make the C# workspace a complete project-review workflow.
