# P1.18 Phase One Direction and CF0 Specialization Review

Work item: P1.18 Phase One Direction and CF0 Specialization Review
Date: 2026-07-10
Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: pause new CF0 semantic probes; continue only through a generalization/second-benchmark gate or a bounded workbench projection.

## Scope

P1.18 reviews the post-correction Phase 1 work from P1.R through P1.17. It evaluates whether the project is still following the corrected semantic-overlay thesis or drifting into CF0-specific fixture hardening.

This is a planning and quality review slice. It does not add behavior, modify CF0 source, broaden extraction, change B0 generated-code behavior, introduce dependencies, or authorize a larger benchmark.

## Reviewed Evidence

- P1.R through P1.2 reframed IntentGraph as a semantic overlay over existing code.
- P1.3 through P1.7 proved code-first maintenance, additive behavior, and behavior-preserving refactor deltas on CF0.
- P1.8 added a CF0 historical state index.
- P1.9, P1.11, and P1.14 modeled existing CF0 behavior as overlay-only contracts.
- P1.10, P1.12, and P1.15 added negative harnesses for those overlay-only contracts.
- P1.16 consolidated repeated overlay-contract negative harness mechanics.
- P1.17 proved current CF0 overlay coverage against extracted code facts.

## What P1 Has Proven

P1 has successfully shown that the corrected model is viable for a tiny code-first maintenance fixture:

```text
D = (I, C, X, M, E, A, H)
```

CF0 now demonstrates:

- hand-written source remains the implementation source
- code facts are extracted from source
- Intent Units refer to code facts and source artifacts instead of containing code text
- additive behavior can update code and overlay together
- refactors can preserve stable intent while implementation facts change
- existing behavior can be added to the overlay without changing source
- evidence, authority, and semantic history can be required for accepted units
- bad deltas fail deterministically
- current overlay coverage can be reported without source text equality or hidden generated-code snapshots

This is meaningful. It is no longer just graph-as-source theory.

## Specialization Risk

The risk is now elevated. CF0 is a tiny single-file Python CLI calculator. It is intentionally narrow. It does not prove:

- multi-file mapping
- cross-module code facts
- UI or workflow surfaces
- larger behavior decomposition
- non-Python extraction
- external code intelligence integration
- real workbench usability
- AI proposal quality in a realistic codebase
- evidence and authority integration beyond local fixture records

More CF0 behavior/contract slices would mostly improve one fixture rather than test the architecture.

## Direction Decision

Do not add another CF0 semantic behavior or overlay-only contract probe by default.

Allowed next work:

- a plan-only second benchmark/generalization gate
- a small workbench projection that visualizes already-proven CF0 coverage/history without adding semantic scope
- documentation cleanup that reduces stale roadmap wording

Not allowed without a new Coordinator decision:

- another CF0 behavior/contract unit
- a larger benchmark implementation
- a broad extractor
- a generic negative-probe framework
- a UI/workbench product beyond a bounded projection
- a claim that CF0 proves general IntentGraph scalability
