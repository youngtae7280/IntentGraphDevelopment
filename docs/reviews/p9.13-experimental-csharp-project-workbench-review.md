# P9.13 Experimental C# Project Workbench Review

Date: 2026-07-13

## Decision

P9.13 passes its bounded implementation gate. It creates the missing project-state layer above the P9.12 fact-only C# workbench without pretending that a syntax snapshot already has accepted intent mappings or source changes.

## Delivered

- separate local project workspace containing an immutable nested C# fact snapshot and mutable semantic-overlay state
- commands to record an explicit user work request and a declared, unaccepted mapping candidate
- one unified static workbench projection containing code facts, work items, Intent Units, mapping links, verification, evidence, authority, and history
- a visible no-proposal/no-delta/no-code-diff state rather than an empty or fabricated change view
- local bundled Cytoscape runtime, graph pan/zoom/fit, selection inspector, filters, work queue, and resizable side panels

## WindowsUtility Evidence

The WindowsUtility demonstration has 8,137 code nodes and 7,931 code relations from the validated C# snapshot, plus 10 semantic-overlay nodes. It records one startup-inspection work request and one candidate mapping to a real extracted `App` type fact.

The output validates deterministically. A repeat run from the same snapshot and project state produced byte-identical HTML, JSON, manifest, validation report, and local graph assets.

The HTML contains the graph interaction contract, but it has not yet received automated browser interaction evidence because the available browser surface rejects new local `file://` pages. This review does not treat structural HTML validation as a substitute for that visual gate.

## Negative Evidence

The repeatable P9.13 harness rejects:

- wrong project-state role
- physical-path leakage
- unknown code fact mapping
- mismatch between mapping record and work-item state
- target-write or automatic-code-application authority promotion
- premature change proposal insertion
- existing output overwrite

## Preserved Boundary

- no external source-project mutation
- no source content or external absolute path in the projection or HTML
- no automatic Intent mapping, accepted mapping, code application, UI approval, graph mutation, network, credentials, build, launch, or productization claim
- no resolved call graph; syntax invocation records remain syntax observations

## Remaining Product Gap

P9.13 is the **beginning** of the daily-use product workflow, not the finish line. A usable project flow still needs a reviewed mapping/ambiguity path, deterministic proposal and delta artifacts, code/graph diff rendering when proposals exist, verification/evidence attachment, and persistent packaging or local application UX. Those layers must be added as integrated slices, not as isolated report pages.
