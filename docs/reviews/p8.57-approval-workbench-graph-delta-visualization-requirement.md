# P8.57 Approval Workbench Graph Delta Visualization Requirement Record

Work item: P8.57 Approval Workbench Graph Delta Visualization Requirement Record
Date: 2026-07-10
Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: future approval workbenches must show an interactive graph, graph delta, selected node/edge details, code diffs for code nodes, and before/after graph diffs for changed existing nodes and edges.

## Scope

P8.57 records coordinator feedback that approval-stage workbenches cannot remain card/table/report-only surfaces.

This slice is a requirement record. It does not implement the graph workbench, extract packages, launch the packaged app, mutate WindowsUtility, create releases, or claim productization readiness.

## Requirement

The approval workbench must show:

- graph nodes and edges visually, with pan/zoom and search/filter.
- graph delta state: added, removed, changed, impacted, and unchanged elements.
- clickable nodes and edges.
- a details panel populated from the selected node or edge.
- selectable delta steps that highlight affected graph elements.
- code diffs when selecting code nodes or code-affecting delta steps.
- graph before/after diffs when existing nodes or edges changed.

## Diff Requirements

Code diff is required when:

- selected node is a code node affected by the current delta.
- selected delta step affects code refs.
- selected graph element links to changed code facts.

Graph element diff is required when:

- an existing node changes attributes, labels, status, refs, evidence, authority, history, or delta links.
- an existing edge changes relation kind, source, target, status, confidence, provenance, refs, evidence, authority, history, or delta links.

If a code-affecting delta has no code diff, the workbench must show a blocker.

If a changed node or edge has no before/after graph diff, the workbench must show a blocker.

## Productization Impact

Package verification authorization is deferred. The next slice should plan the graph delta approval workbench boundary before asking the user to approve further package execution or release-related gates.
