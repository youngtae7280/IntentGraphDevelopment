# P1.19 Second Benchmark and Generalization Gate Review

Work item: P1.19 Second Benchmark and Generalization Gate - Plan Only
Date: 2026-07-10
Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: continue into Phase B planning with `B1-typescript-rest-api`; do not implement the benchmark in P1.19.

## Scope

P1.19 is a plan-only generalization gate after P1.18. Its job is to prevent the project from continuing to overfit CF0 and to prevent a late-discovery repeat of mature code graph systems.

This slice does not implement a new benchmark, add code facts, create extractors, build UI, add dependencies, or broaden product claims.

## Reviewed Evidence

- P1.18 concluded that CF0 is saturated proof evidence.
- CF0 proves the semantic-overlay model on a tiny single-file Python CLI fixture.
- CF0 does not prove multi-file mapping, cross-module code facts, non-Python extraction, route/service/test relationships, workbench usability, or realistic AI proposal quality.
- The Product Capability Roadmap defines Phase B as Fast Retrofit and Code Facts.
- The prior-art map already identifies strong code graph and code intelligence systems.

## Prior-Art Refresh

P1.19 refreshed the code-intelligence prior-art pressure using primary sources:

| System | Relevant strength | P1.19 decision |
|---|---|---|
| Graphify | AI coding context graph over code and other artifacts | Learn/differentiate; do not treat AI context graph as authority. |
| Tree-sitter | Incremental parsing and syntax trees | Learn/borrow for syntax extraction pressure. |
| SCIP / LSIF | Persisted language-agnostic code intelligence facts | Learn from fact/index shapes. |
| Kythe | Cross-reference indexing and generated-code mapping | Learn from source/generated mapping provenance. |
| Glean | Typed code facts, references, calls, hierarchies at scale | Learn from fact store boundaries. |
| CodeQL | Querying code as data for semantic/static analysis | Keep static-analysis engine out of Phase B. |
| Joern / CPG | Code property graph for code/security analysis | Keep CPG/static-analysis scope out of Phase B. |

Conclusion:

IntentGraph should not build a broad code graph engine. Phase B should build the overlay-facing contract for accepting, validating, and mapping code facts from a bounded benchmark and later from stronger tools.

## Phase B Entry Criteria

Phase B implementation may begin only when:

- B1 source shape is documented before fixture creation.
- Code fact schema v0 is defined before broad extraction.
- Prior-art decision 011 remains accepted or is revised.
- The first extractor is bounded to B1 and does not claim broad language support.
- Verification criteria are written before implementation.
- No UI/workbench/productization work is included in the same slice.

## Phase B Allowed First Implementation Slice

Recommended next slice:

```text
P2.0 B1 TypeScript REST Code Fact Schema and Static Fixture
```

Allowed:

- create a tiny B1 TypeScript REST-style fixture
- define code fact schema v0 for B1
- write a deterministic B1 extraction report or fixture-backed fact file
- validate relation endpoints, source digests, source ranges or explicit range status, extractor identity, confidence, and relation kind allowlist
- add negative probes for unknown kind, missing endpoint, stale digest, and missing provenance

Not allowed:

- broad all-language extraction
- Graphify/CodeQL/Joern/Kythe/Glean/SCIP clone
- UI/workbench product
- AI proposal generation
- automatic authority
- source code replacement claim

## P2.0 Pass Criteria

P2.0 passes only if:

1. B1 fixture is small, deterministic, and multi-file.
2. Code facts are stable across repeated runs or canonical serialization.
3. Every relation endpoint resolves.
4. Every fact includes source file, source digest, extractor id, extractor version, confidence, and range or range-status.
5. A one-file change plan exists for incremental extraction validation.
6. Negative probes prove invalid facts fail deterministically.
7. The report states what is built locally and what remains a future adapter/integration.

## P2.0 Stop Conditions

Stop before implementation expands if:

- source text becomes the graph authority
- facts are nondeterministic
- relation endpoints are unresolved
- extractor grows beyond B1 without a prior-art decision
- UI/workbench or AI planning starts in the same slice
- TypeScript support requires a broad parser/indexer dependency without a decision record
