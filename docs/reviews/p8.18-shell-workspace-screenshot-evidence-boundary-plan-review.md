## Scope

P8.18 defines the boundary for future WindowsUtility screenshot evidence after P8.17 proved sandboxed UI launch feasibility.

This slice is plan/report-only. It does not capture a screenshot, interact with the UI, invoke hardware actions, edit source, apply proposals, grant AI authority, or claim productization readiness.

## Screenshot Evidence Constraints

Future screenshot evidence must:

- launch only the sandboxed `WindowsUtility.App.exe`.
- capture only the sandboxed app window, not the original target repo or unrelated desktop content.
- write screenshot artifacts only into IntentGraphDevelopment generated evidence paths.
- terminate the sandboxed app after capture.
- prove the original WindowsUtility target remains clean/aligned.
- avoid device commands, firmware actions, printer actions, network writes, card movement, dump capture, and other hardware-sensitive flows.

## Allowed Future Probe Shape

The next safe screenshot probe should:

1. create a disposable sibling sandbox;
2. build in the sandbox;
3. launch the sandboxed app;
4. discover the main window title `Card Printer Utility`;
5. capture the window rectangle to a PNG artifact;
6. close the sandboxed app;
7. remove the sandbox;
8. emit a screenshot evidence report;
9. verify original target state before and after.

## Blocking Conditions

Block screenshot capture if:

- the app does not launch or no window is discovered.
- capture tooling cannot target the app window specifically.
- capture would require interacting with hardware-sensitive UI.
- capture would write into the original WindowsUtility target repo.
- the original target repo is dirty or stale.
