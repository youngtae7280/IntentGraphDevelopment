# P9.21 Guided Review Proposals Review

Date: 2026-07-13

## Decision

P9.21 passes the guided review-proposal boundary.

The previously available proposal route required users to prepare a full JSON artifact. The new form records a bounded review proposal from a work item and its already declared mapping. It is not automatic proposal generation: the user provides the proposal title, review summary, verification requirement, and evidence requirement; the local workspace only derives recorded IDs and code-fact references.

## Evidence

- `tools/run_experimental_csharp_project_server_smoke.py` passes 19 probes.
- `tools/run_experimental_csharp_guided_proposal_negative_probes.py` passes 7 deterministic failure probes.
- the guided positive baseline records no code diff and reports `guidedReviewProposal: true`.
- snapshot source provenance remains unchanged in both flows.
- the public CLI facade creates the same zero-diff, non-applied proposal from a declared mapping in an isolated local workspace.
- static workbench emission and validation remain deterministic and read-only; a fresh emission matched the committed P9.21 HTML, projection, manifest, validation report, and local graph assets by SHA-256.
- the loopback browser workbench loaded the complete WindowsUtility projection (8,188 nodes and 8,040 relations) without console errors; regular code-fact labels stayed hidden until a node is selected, changed, or found through search.

## Product Result

The local daily-use review flow is now:

```text
request -> declared code mapping -> guided review proposal -> graph delta inspection -> review receipt
```

JSON import remains an advanced route for a proposal that has a separately prepared code-diff artifact.

## Non-goals

- no AI proposal generation
- no source change, patch synthesis, graph-delta application, build, test, or runtime evidence execution
- no approval, credential access, provider call, or remote service

## Remaining Gap

Review receipts still require JSON import. The next useful usability slice is a guided receipt form that records which proposal requirement pair was reviewed, while retaining the strict non-executing boundary.
