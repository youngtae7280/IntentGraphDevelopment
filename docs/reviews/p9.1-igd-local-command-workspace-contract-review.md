# P9.1 IGD Local Command and Workspace Contract Review

Work item: P9.1 IGD Local Command and Workspace Contract

Date: 2026-07-13

Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: the bounded B1 review workflow is available through one local command facade and one declared workspace contract. It is a developer-preview implementation slice, not an installable or general-purpose product.

## Implementation

`tools/intentgraph.py` provides three local-only subcommands:

- `init-sample` creates a fresh B1 workspace and copies only the bounded fixture inputs.
- `validate` fails closed on malformed manifest data, path escape, stale source provenance, missing inputs, unsupported outputs, or authority escalation.
- `review` runs the existing B1 extraction, code-fact validation, mapping verification, non-applied proposal validation, consistency verification, and static workbench projection inside the workspace.

The manifest fixes every output under `artifacts/` and requires all mutation, provider, credential, network, hook, code-application, and release authority flags to remain false.

## Evidence

The fresh workspace workflow passed from initialization through a generated `workbench.html`.

The same workspace was reviewed a second time. Code facts, code-fact validation, mapping, proposal validation, consistency, workbench projection, workbench HTML, and workbench validation retained their byte digests.

The historical direct B1 extraction-to-workbench pipeline also passed after the P9.1 addition.

`tools/run_igd_workspace_negative_probes.py` reruns a positive baseline review and passed fourteen deterministic probes:

- wrong workspace role
- target mutation enabled
- automatic code application enabled
- network, provider API, credential access, hook installation, or release publishing enabled
- unsupported profile
- source path traversal
- output outside `artifacts/`
- stale source provenance
- missing proposal
- stale materialized proposal baseline

## Baseline Materialization Boundary

The historical B1 proposal binds to an aggregate code-facts digest that includes its physical `sourceRoot`. A copied source tree therefore has an equivalent semantic fact set but a different aggregate digest. `init-sample` derives only the copied workspace proposal baseline; it does not alter source text, modify the original proposal, include a patch, or apply a proposal.

This is an explicit P9.1 compatibility boundary, not the desired long-term identity model. P9.2 must replace path-dependent aggregate baseline binding with a logical source identity and profile contract.

## Non-Goals Preserved

- no target repository mutation
- no automatic code application or proposal acceptance
- no network/provider/credential/hook activity
- no package manifest, installer, signing, release, or productization claim
- no arbitrary repository or language support

## Recommendation

Continue to `P9.2 Logical Workspace Source Identity and Profile Contract`. It must first plan and validate the logical source-root/digest representation before broadening supported projects.
