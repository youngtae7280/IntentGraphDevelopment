# P8.23 Shell Workspace Workbench Usability Boundary Plan

Work item: P8.23 Shell Workspace Workbench Usability Boundary Plan
Date: 2026-07-10
Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: pass; a bounded usability dry run is required before richer workbench UI or productization.

## Scope

P8.23 defines how to judge whether the WindowsUtility shell/workspace workbench is useful for review.

This slice is plan/report-only. It does not change the workbench, run a user study, mutate WindowsUtility, apply proposals, grant AI authority, grant hardware authority, or claim productization readiness.

## Evaluation Question

The workbench should be considered useful only if a reviewer can answer the core adoption questions faster and with fewer missed safety boundaries than by opening raw JSON files manually.

## Required Review Tasks

The next usability dry run should ask a reviewer to answer:

1. Which shell/workspace mapping is accepted?
2. Which source refs are covered by the accepted mapping?
3. Is the proposal applied or still non-applied?
4. Which evidence proves build, UI launch, and screenshot status?
5. Did the original WindowsUtility target remain unchanged?
6. Which safety flags remain false?
7. Which artifact proves the screenshot exists and what digest identifies it?
8. What is the next recommended action?

## Comparison Baseline

The dry run must compare:

- workbench path: use the static HTML projection first.
- raw path: inspect the underlying JSON artifacts directly.

The report may be self-conducted for this early slice, but it must state that it is not a human usability study unless a separate human reviewer participates.

## Metrics

The dry run should record:

- task count
- answer correctness count
- missed safety-boundary count
- artifact lookup count
- time-to-answer estimate or measured duration
- whether screenshot evidence was found
- whether authority false flags were found
- whether raw JSON required more file hops

## Pass Criteria

The dry run may pass only if:

| Criterion | Required result |
|---|---|
| all required review tasks answered | Pass |
| no safety false flag missed | Pass |
| screenshot artifact found | Pass |
| target unchanged state found | Pass |
| proposal non-applied state found | Pass |
| workbench path uses fewer artifact lookups than raw JSON path | Pass |
| no source mutation or productization claim introduced | Pass |

## Blocking Conditions

Block richer UI or productization if:

- reviewers cannot find authority false flags from the workbench.
- screenshot evidence is not discoverable.
- workbench answers conflict with raw JSON.
- workbench requires opening the same number of raw files for the core questions.
- productization or proposal application is implied by the UI.
