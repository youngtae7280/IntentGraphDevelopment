# P9.2 Logical Workspace Source Identity and Profile Contract Review

Work item: P9.2 Logical Workspace Source Identity and Profile Contract

Date: 2026-07-13

Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: the B1 local-review profile now binds to a stable logical source identity, so its workspace artifacts no longer depend on the physical workspace directory.

## Implementation

`tools/extract_b1_code_facts.py` accepts an optional `--source-root-id`. With that option it emits a validated `intentgraph://` `sourceRoot` and `sourceRootKind: logical-id`. Without the option, historical direct B1 output remains unchanged.

The B1 local-review workspace schema is now `0.2.0`. It requires the profile ID and logical source identity `intentgraph://profiles/b1-typescript-rest-api-sample/source`. The workspace copies a declared P9.2 proposal template whose baseline already binds to the logical code-facts digest. Init no longer computes or rewrites a proposal baseline for each physical workspace path.

## Verification

- two fresh workspaces at different filesystem paths completed the full six-step review workflow
- every artifact in their `artifacts/` directories, including the static workbench and review report, was byte-identical
- the existing physical-path B1 extraction output remained byte-identical
- the existing B1 direct pipeline and all existing B1 negative harnesses passed
- the workspace negative harness passed 16 probes, including wrong logical IDs, wrong profile proposal identity, authority escalation, stale source provenance, and stale proposal baseline
- the logical extractor/validator harness passed 5 probes: three invalid logical extractor inputs and two invalid logical code-fact identity records

## Boundary

Logical source identity changes only the portable aggregate identity of a declared workspace profile. It does not hide the source digest, grant source mutation, apply proposals, call a provider, access credentials, install hooks, package a product, or claim release readiness.

The B1 profile is still deliberately narrow. This result proves portability across workspace locations, not arbitrary-project support.

## Recommendation

Continue to `P9.3 External Project Profile Intake and Workspace Import Boundary Plan`. The next step must define how a user project supplies a declared profile and source root without accepting unbounded extractor, mutation, or network authority.
