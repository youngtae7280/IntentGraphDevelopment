# P9.7 C# Profile Reuse and Dependency Boundary Gate Review

Date: 2026-07-13

Decision: permit only an experimental host-SDK availability preflight. Do not add a reusable C# extractor, a package dependency, or an installation claim.

## Rationale

P9.6 proves that local SDK Roslyn can parse one realistic C# target deterministically under a strict read-only boundary. The probe depends on whichever SDK MSBuild selects, and the environment contains multiple SDK versions with no repository `global.json`. That fact prevents treating the host path as a portable product dependency.

An explicit preflight is useful because it turns a hidden environmental assumption into visible, deterministic evidence. It does not expand extraction authority: it need not read a target source tree or execute a target build.

## Accepted P9.8 Boundary

- inspect only local SDK metadata and required Roslyn binary presence
- emit a local report with an experimental, host-specific availability result
- fail closed for missing/unsupported SDK or missing binaries
- preserve false flags for network, target read/mutation/build/launch, package restore/install, provider, credential, hook, code application, release, and productization authority

## Rejected Claims

- P9.6/P9.7 do not prove arbitrary C# support
- host SDK availability is not a pinned dependency or distribution contract
- syntax invocation facts are not semantic call resolution
- no C# code fact is yet integrated into the public `intentgraph` local-review workspace profile

## Recommendation

Continue to `P9.8 Experimental Host-SDK C# Profile Availability Preflight`. Revisit pinned Roslyn packaging only after P9.8 emits stable diagnostics and a separate dependency/release gate authorizes that work.
