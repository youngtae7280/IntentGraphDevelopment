## Scope

P8.16 defines the boundary for future WindowsUtility UI launch or screenshot evidence after P8.15 proved sandboxed build evidence.

This slice is plan/report-only. It does not launch the WPF app, capture screenshots, invoke UI automation, perform hardware actions, edit source, apply proposals, or claim productization readiness.

## UI Evidence Risks

UI evidence is more sensitive than build evidence because it can:

- start a long-running WPF process.
- load `SmartComm2.dll` and related Native boundaries.
- require an interactive desktop session.
- create runtime files in the sandbox.
- accidentally drift from evidence collection into product validation claims.

The original WindowsUtility repo must remain untouched.

## Allowed Future Probe Shape

The next safe UI evidence probe should:

1. create the same sibling sandbox shape used by P8.15;
2. build in the sandbox;
3. launch only the sandboxed `WindowsUtility.App.exe`;
4. record process start, window discovery if available, and clean process termination;
5. avoid printer/device commands, firmware, network writes, card movement, print, dump capture, and hardware actions;
6. optionally capture a screenshot only if the capture tool can do so without modifying the original target;
7. verify the original WindowsUtility repo is clean/aligned after the probe.

## Required Stop Conditions

Stop before launch if:

- sandbox build fails.
- original target is dirty or stale.
- the launch path points to the original target instead of the sandbox.
- the probe requires hardware/device access.
- the probe requires source edits.

Stop after launch if:

- the process does not exit on request.
- the UI cannot be observed without manual intervention.
- the app attempts hardware/device actions.
- screenshot capture would require writing to the original target.
