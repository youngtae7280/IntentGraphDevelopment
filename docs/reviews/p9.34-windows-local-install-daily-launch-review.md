# P9.34 Windows Local Install And Daily Launch Review

## Decision

P9.34 passes as the first installable Windows-local preview of the IntentGraph Local Review Kit.

The product can now be built as a deterministic directory/ZIP, installed without a repository checkout, invoked through `igd`, opened against an ordinary C# source directory, resumed when source facts are current, served on loopback, and uninstalled without deleting user review projects.

This is not a public release or a claim of broad language support.

## Delivered

- `igd doctor`
- `igd prepare <C# source root>`
- `igd status <C# source root>`
- `igd open <C# source root>` with automatic port selection and browser launch after readiness
- path-hashed local project identity without an absolute source path in the launch record
- atomic first creation and fail-closed stale-source resume
- one-process-per-project OS lock spanning creation, atomic commit, resume, and serving
- deterministic Windows directory and ZIP bundle with file digests
- reparse-free C# intake with strict resolved-file containment
- exact one-file-fact-per-source-digest validation
- per-user installer, PATH shadow refusal, PATH opt-out, exact-inventory uninstaller, and runtime/user-data separation
- immutable installed runtime execution with system temporary/cache storage
- repeatable launch, loopback server, bundle, and installed-runtime verification

## Problems Found And Corrected

1. The old C# validator required every WindowsUtility fact and relation kind in every project. It now accepts any supported subset while still requiring valid file facts, provenance, endpoints, ordering, and known kinds.
2. The original staging path exceeded Windows path limits on WindowsUtility. Product workspace keys and staging paths are now short and hash-based.
3. The first installer default colocated runtime and user data. Runtime now installs under `%LOCALAPPDATA%\Programs\IntentGraph`; uninstall preserves `%LOCALAPPDATA%\IntentGraph`.
4. An installed batch-launch smoke initially killed only the batch parent. The repeatable harness now terminates the process tree and proves the Workbench session lock is released.
5. Parallel `igd open` processes could own one project. An OS-backed session lock now rejects the second process and recovers automatically after process exit.
6. Browser launch could race server startup. It now waits for the loopback revision endpoint before opening the browser.
7. The original uninstaller trusted only the manifest role and launcher. It now validates the complete file/directory inventory, hashes and lengths, rejects every reparse point, and deletes only rechecked recorded entries and known empty directories.
8. C# intake rejected symbolic links but could accept Windows directory junctions. Intake now inspects reparse attributes and requires every resolved source entry to remain beneath the source root.
9. Syntax validation accepted any number of file facts. It now requires exactly one file fact for every source digest entry.
10. The project lock began after preparation. A stable lock beside the project now covers the first existence check, all preparation and resume validation, the atomic same-volume commit, and serving.
11. Installed Python imports and Roslyn staging could write under the runtime. The launcher disables bytecode writes and redirects cache state, while C# probe work uses system temporary storage.
12. PATH-enabled installation could be shadowed by another `igd.cmd`. Installation now fails closed on an existing effective launcher and verifies the new command resolution.
13. Browser launch lacked bounded positive and failure-path evidence. The server smoke now injects readiness and browser helpers to prove ordering, retry bounds, readiness failure suppression, and browser-open failure without opening a real browser.

- Windows bundle negative probes: 13/13 pass

  closed loopback port, and released project session lock

- PATH shadowing and default `igd` command resolution are both exercised
- uninstall rejects unknown files/directories, modified manifest files, and junctions, then removes the valid runtime while preserving user data

## Preserved Boundaries

- no target build, restore, launch, source mutation, or proposal application
- no provider, credential, external network, hook, signing, or release operation
- no automatic intent mapping, evidence acceptance, or approval
- no source path persisted in the launch record
- no user review project removal during normal uninstall
- no real browser opened by readiness/failure observation smokes

## Remaining Product Gaps

- changed source cannot yet be refreshed while preserving and invalidating semantic records correctly
- installer upgrade/repair and rollback are not implemented
- a later PATH change can introduce a new shadowing launcher after installation
- script-level uninstall validation minimizes but cannot eliminate a same-user concurrent filesystem race between the final recheck and each removal
- runtime still requires host Python and .NET SDK
- product resources still originate from historical repository locations before bundling
- the artifact is unsigned and unpublished
- editor, GitHub, team policy, and multi-user coordination remain absent

## Recommended Next Slice

P9.35 should implement a reviewed `igd refresh` boundary: capture a new immutable snapshot, compute code-fact delta, mark stale mappings and proposals, preserve evidence/authority/history, and require explicit review before changing the active project revision. This is now the largest blocker to ordinary repeated daily use.
