# P9.26 Dense Graph Visual Navigation Review

Date: 2026-07-13

## Decision

P9.26 passes the dense-graph zoom, visual contrast, compact layout, and bounded work
history rendering boundary.

## Evidence

- the WindowsUtility projection loads 8,179 nodes and 7,978 relations in one
  Cytoscape instance
- full-graph fit begins at zoom 0.388 on a 1600 by 1000 browser viewport
- pointer-centered wheel zoom reaches 100 with `maxZoom: 100` and enters the `micro`
  visual band
- deep browser inspection shows distinct code facts and relation lines rather than
  the former approximately three-pixel invariant dots
- semantic nodes use dark chromatic cores, rasterized refraction/grain material,
  luminous category rims, and bounded underlay rings; ordinary code facts remain
  texture-free and use kind-specific geometry, while file landmarks reuse the one
  shared texture
- compact relation-aware placement and 26-pixel fit padding reduce unused canvas
  area while preserving deterministic non-physics layout
- work search reduces the three-item live fixture to one matching card; the unmapped
  status filter shows two cards
- the DOM render limit remains 60 work cards while all work records remain available
  through filtered previous/next navigation
- eleven consecutive zoom-in actions with a relation already selected settle at zoom
  100 in 846 ms on the browser QA fixture; the selected relation remains the only
  highlighted relation and renders at 1.6 screen pixels before and after zooming
- server smoke passes 21 probes; static emission/validation, Python compilation, and
  inline static/server JavaScript parsing pass

## Performance Notes

- pan and wheel gestures do not rebuild the graph or recompute layout
- the renderer changes collection styles only after a 350 ms interaction-settle
  boundary and only when crossing one of nine zoom bands
- glow/underlay is disabled for ordinary code facts and reserved for the much smaller
  semantic, capsule, file, search, stage, and selection surfaces; one shared material
  texture is reused instead of creating one image per node
- ordinary and selected relation widths remain compensated below two screen pixels at
  maximum zoom instead of inheriting the former minimum model-space width
- the graph keeps `textureOnViewport`, motion blur, and hidden edges during viewport
  motion

## Correctness Notes

- `code` is the node category and `method` is a code-fact kind; no duplicate peer
  node is introduced for a method
- this slice changes only projection positions and styles plus work-list navigation
  controls; graph records and source facts are unchanged

## Non-goals

- no dynamic force simulation during interaction
- no source or graph mutation
- no automatic mapping, planning, proposal application, verification execution,
  evidence collection, authority promotion, or approval

## Next Boundary

Continue real-project interaction review. Add another layout or styling abstraction
only when measured navigation or a second project demonstrates a repeatable need.
