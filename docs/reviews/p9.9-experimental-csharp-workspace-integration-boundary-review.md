# P9.9 Experimental C# Local Workspace Integration Boundary Review

Date: 2026-07-13

Decision: authorize a bounded P9.10 fact-only snapshot workspace probe, subject to P9.8 preflight and zero target authority.

## Why Snapshot First

Running extraction directly over an external repository would blur source provenance, physical paths, and target-state authority. A workspace snapshot keeps the external project immutable and makes the extracted fact set reproducible from a declared copied source boundary.

P9.4 already demonstrates this pattern for one bounded TypeScript profile. P9.10 may adapt the safety mechanics, but must not claim that the B1 importer supports C# or arbitrary project shapes.

## Why Fact-Only

The C# profile has no reviewed Intent Unit mapping, proposal, or consistency verifier. Creating one while introducing the workspace would conflate Phase B extraction with later mapping/change stages. P9.10 therefore stops after source receipt plus code facts.

## Required Boundary

- preflight availability must pass before source intake
- source snapshot is C# only and never includes `bin`/`obj`, project evaluation inputs, or binaries
- external absolute paths remain ephemeral command inputs and cannot persist
- code facts originate from the local snapshot and remain syntax-only
- WindowsUtility and every other external source tree remain unchanged

## Recommendation

Implement `P9.10 Experimental C# Snapshot Workspace and Fact Extraction Probe`, then review its intake/fact evidence before considering mappings, workbench integration, or dependency packaging.
