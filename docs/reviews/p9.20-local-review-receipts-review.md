# P9.20 Local Review Receipts Review

Date: 2026-07-13

## Decision

P9.20 passes the bounded review-receipt gate.

P9.19 let a user record a deterministic non-applied proposal, but its required verification and evidence records could only remain passive text. P9.20 adds a typed, user-supplied receipt boundary for an individual requirement pair. It records review state without treating that record as execution evidence or approval.

## Evidence

- `tools/run_experimental_csharp_project_server_smoke.py` passed 18 probes.
- The loopback smoke records request, mapping, proposal, and receipt; reloads the receipt state; rejects an applied proposal and an executing receipt claim; and preserves snapshot provenance.
- `tools/run_experimental_csharp_review_receipt_negative_probes.py` passed 8 deterministic failure probes.
- The static WindowsUtility workbench emitted and validated successfully.
- Browser review confirmed that the full graph remains loaded after the visual revision. This historical note is superseded by P9.22's flat community-point treatment: the project marker is directly labeled, while semantic records and code facts use an impact/focus lens, search, or selection. Zoom compensates node, edge, and label scale so visual marks do not grow or shrink in direct proportion to graph-space zoom.

## Product Result

The local Workbench can now carry a work item through:

```text
request -> declared mapping -> review-only proposal -> delta/diff inspection -> non-executing review receipt
```

It uses one complete local graph and keeps source, graph application, verification execution, evidence execution, and approval separate from recordkeeping.

## Remaining Gap

P9.20 records review evidence but does not execute an evidence requirement. P9.21 subsequently removes the analogous JSON-only bottleneck for review proposals, but it does not change this execution-evidence boundary. A future local verifier-result import or sandboxed evidence-run receipt must keep an explicit distinction between a user review record and tool-generated execution evidence.
