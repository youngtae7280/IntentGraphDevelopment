# P9.0 IGD Productization Entry Boundary Plan Review

Work item: P9.0 IGD Productization Entry Boundary Plan

Date: 2026-07-13

Reviewer: IntentGraphDevelopment Roadmap Orchestrator

Decision: define `igd-local-review-kit` as the first IntentGraphDevelopment product build path; do not claim it is built, installable, released, or accepted.

Candidate state: `defined-but-not-built`.

## Evidence Reviewed

- Phase H requires an installable CLI or app, configuration, onboarding, sample workflow, release checklist, compatibility matrix, and security/privacy boundary documentation.
- The repository has 64 Python tools and 63 separate `argparse` entry points, but no package manifest, single public command, install contract, or supported-project configuration contract.
- Existing B1 and WindowsUtility workbench outputs demonstrate valuable pieces of the intended experience, including graph/delta/code/evidence/authority inspection, but not a reusable product workflow.
- P8.124 correctly separates WindowsUtility target-delivery evidence from IntentGraphDevelopment productization.

## Candidate Definition

The product under construction is the **IntentGraph Local Review Kit**. Its core contract is review-first and local-only: prepare a declared semantic-overlay workspace, validate it deterministically, and inspect it in an interactive local workbench before a human records a decision.

The candidate deliberately excludes automatic target writes, self-authorization, remote provider actions, credentials, GitHub automation, editor integration, installers, signing, and release publishing.

## P9.1 Gate

The next bounded implementation slice may create a single local command facade and workspace contract. It must prove that a fresh workspace can host a deterministic B1 sample workflow without relying on a WindowsUtility-specific path or a manually assembled collection of commands.

P9.1 must fail closed for:

- missing or malformed workspace configuration
- undeclared output paths
- target-repository mutation requests
- code-application flags
- network, credential, provider, hook, or release options
- artifacts that lack provenance or authority state

## Non-Goals Preserved

- no installer or release artifact
- no signing, certificate, token, or credential access
- no provider API or network call
- no WindowsUtility package/release action
- no claim that the candidate is ready for public or team use

## Recommendation

Continue to `P9.1 IGD Local Command and Workspace Contract`. Before that implementation, define the workspace manifest and CLI command grammar as source-controlled contracts with repeatable negative probes.
