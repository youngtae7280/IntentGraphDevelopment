## Scope

P8.68 creates the explicit user/coordinator authorization request for the next packaged artifact verification step.

This slice is request-only. It does not extract the package, run the packaged executable, launch packaged UI, capture packaged UI screenshots, create installers, sign artifacts, read credentials, call provider APIs, publish releases, modify WindowsUtility, grant AI authority, or claim product readiness.

The current-goal `accept/revise/blocked` shortcut is not applied to this authority request because package extraction and packaged artifact verification are separate productization authorities.

## Authorization Request

Question:

```text
Authorize the next slice to perform bounded sandboxed extraction inventory verification of the existing WindowsUtility package artifact?
```

Recommended response:

```text
accept sandboxed package extraction inventory verification
```

Allowed responses:

- accept sandboxed package extraction inventory verification
- reject packaged artifact verification
- revise package verification scope first

## What Acceptance Would Mean

If the user accepts, a later slice may verify the existing package artifact by extracting only a sandbox copy and comparing extracted inventory facts.

Acceptance would authorize:

- using a temporary sandbox directory
- copying the existing package artifact into that sandbox
- extracting the sandbox copy
- listing extracted files
- hashing extracted files
- comparing extracted inventory to the existing manifest
- writing verification reports under `generated/`

Acceptance would not authorize:

- packaged executable launch
- packaged UI launch
- packaged UI screenshot capture
- WindowsUtility source edits
- WindowsUtility commit or push
- installer creation
- artifact signing
- credential access
- provider API calls
- release tag creation
- release publishing
- productization claim
