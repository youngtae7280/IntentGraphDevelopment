# P9.25 Durable Work History Navigation Review

Date: 2026-07-13

## Decision

P9.25 passes the durable work-stage revision and single-Workbench history navigation
boundary.

## Evidence

- every new request, mapping mutation, proposal/requirements write, and review receipt
  write returns and persists a stable revision ID
- revision records preserve per-work sequence/predecessor links and one global
  before/after work-history digest chain, including interleaved work items
- ten repeatable negative probes reject missing fields, unknown stage/record/diff
  references, noncontiguous sequences, broken predecessors, broken global digests,
  stale latest-state digests, duplicate delta IDs, and authority promotion
- the loopback smoke passes 21 probes with two independently navigable work items and
  five durable revisions
- the project Workbench exposes previous/next work and previous/next stage controls;
  browser checks moved from work 2/2 to 1/2 and through stages 1/5, 2/5, and 3/5
- stage browser checks showed distinct revision IDs and before/after digests while the
  focused graph changed from request additions to mapping additions and proposal delta
- an external CLI mutation changed an already open live Workbench from two work items
  to three after the local revision-head poll, without repeatedly polling the full
  graph projection
- static HTML emission/validation, Python compilation, and inline JavaScript parsing
  pass

## Correctness Notes

- the work-history digest excludes extractor/foundation refresh state so unrelated
  code-fact refreshes do not break the append-only work lifecycle chain
- proposal and verification/evidence requirement stages intentionally share one
  atomic revision
- pre-P9.25 WindowsUtility records remain explicitly `legacy record-derived`; no fake
  historical digest was backfilled
- `record_semantic_foundation()` was restored after a P9.23 insertion had stranded
  part of its body; its six-probe regression remains passing

## Non-goals

- no full graph snapshot copy per stage
- no retrofit of work performed before IGD recording
- no target source mutation, build, restore, launch, test execution, runtime evidence
  collection, proposal application, acceptance, or approval automation

## Next Boundary

Add a project-level work dashboard with search/status filters and a stable historical
snapshot index when real project adoption produces enough work items to justify
virtualized history browsing. Full before/after graph materialization should be added
only when a real applied-delta boundary exists.
