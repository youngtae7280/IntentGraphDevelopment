## Scope

P8.14 plans how to collect shell/workspace smoke evidence for the accepted WindowsUtility mapping without modifying the WindowsUtility repository.

This slice is plan/report-only. It does not run `dotnet build`, launch the app, collect screenshots, write target `bin/obj`, invoke hardware, apply proposals, or claim productization readiness.

## Evidence Collection Constraint

WindowsUtility source writes remain unauthorized. A normal build in the target repo can write generated files such as `bin/` and `obj/`, so P8.14 does not authorize direct target builds.

Allowed future evidence strategies must satisfy:

- target repo remains clean and aligned before and after evidence collection.
- source files in the target repo are not modified.
- generated build/runtime output is written only outside the target repo or in an explicitly disposable sandbox.
- no hardware/device actions are invoked.
- evidence collection is not proposal application and not productization.

- the proposed run writes to the original target repo.
- the run needs hardware/device actions.
- the run requires source edits.
- the run is presented as proposal application or productization.
