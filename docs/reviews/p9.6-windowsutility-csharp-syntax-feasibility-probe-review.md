# P9.6 WindowsUtility C# Syntax-Only Feasibility Probe Review

Date: 2026-07-13

Decision: pass the bounded feasibility probe. Do not claim reusable C# profile support.

## Evidence

- WindowsUtility `src` was read at clean, aligned revision `ac5b2204442cde751f625a9979a4fdb437d468a8`.
- The source snapshot contains 206 non-generated C# files and has the same digest before and after the probe.
- The Roslyn syntax-only probe emitted 8,137 facts and 7,931 relations. A repeat extraction was byte-identical.
- Every fact ID and relation ID is unique; every relation endpoint resolves.
- Facts carry relative source provenance and digest data, never target absolute paths or source text.
- Invocation facts remain ambiguous syntax observations rather than semantic call edges.
- The committed negative harness passes nine failure cases after rerunning its positive baseline.

## Quality Correction

The first whole-tree run found that nested invocations may share a syntax start position. The original ID rule therefore collided. The parser now includes span length in the deterministic ID, and the whole-tree rerun passed all uniqueness checks. This correction was required before accepting P9.6.

## Preserved Boundary

- WindowsUtility was neither restored, built, launched, changed, committed, nor pushed.
- No source write, hardware access, provider call, credential access, hook, code application, package, signing, release, or IGD product-readiness claim occurred.
- Roslyn is borrowed from the local SDK only for this disposable probe. P9.6 makes no portability, licensing, pinning, or distribution claim.

## Recommendation

Open `P9.7 C# Profile Reuse and Dependency Boundary Gate - Plan Only`. The gate must compare a host-SDK prerequisite, a pinned local adapter, a different parser, and stopping at benchmark-only extraction before any reusable profile implementation starts.
