## Scope

P1.10 adds a repeatable negative-probe harness for the CF0 P1.9 overlay-only contract delta. The harness starts from the committed good P1.9 inputs, mutates copies in temporary directories, runs `tools/verify_code_first_delta.py`, and passes only when every bad input fails for the expected reason.

This is a hardening slice only. It does not add another behavior unit, change CF0 source behavior, create a general negative-probe framework, alter B0 generated-code behavior, or add dependencies.

## Verifier Tightening

P1.10 keeps the verifier changes narrow:

- overlay smoke checks now report mismatch details for exit code, stdout, and stderr
- delta verification checks declared `behaviorChecks`
- overlay-only unsupported-operation contracts must include an explicit `expectedStderr`
- failed overlay verification details are surfaced in the delta report errors

These changes make negative failures inspectable without adding a general planner, full branch semantics, or a broad verifier framework.

## Recommendation

Continue. The next slice can either model another existing CF0 contract, such as invalid integer input, or begin a small review of repeated CF0 harness patterns before adding more semantic coverage.
