# P9.15 Interactive Local Project Workbench Review

Date: 2026-07-13

## Decision

P9.15 passes the bounded local-interaction gate. The Workbench no longer presents the raw code graph as its default user experience, and a user can record a new work request from the local UI without touching the external source repository.

## Corrected Visual Model

P9.14 revealed a projection problem: 8,137 code facts dominated roughly a dozen semantic records. This was a Workbench design error, not evidence that IntentGraph should separate code from intent.

The corrected projection retains one graph while providing layered views:

- overview: 32 nodes, including 17 derived code capsules and 15 semantic records
- active impact: 28 nodes, including the mapped/proposed cancellation chain and containment parents
- code topology: 678 structural nodes
- all records: 8,169 nodes, available only as an explicit deep-inspection lens

## Local Interaction Evidence

The loopback server smoke test proves:

- interactive HTML and the local API are served with a local-only content-security policy
- the project projection is available through the API
- a work request can be recorded through `POST /api/work-requests`
- the next projection contains that request
- duplicate identifiers are rejected
- local Cytoscape assets are served without a CDN
- non-loopback binding is rejected
- the nested source snapshot provenance is unchanged after the project-workspace update

## Boundary Preserved

The server only writes IntentGraph project state. It does not mutate WindowsUtility source, automatically map a request, apply a proposal, record approval, run build/test/launch, access credentials, or contact a remote provider.

## Remaining Product Gap

P9.15 is a useful local single-user starting point, but it is not yet the complete daily product. The next meaningful layers are interactive mapping/proposal authoring, review/decision records, controlled evidence execution, reusable workspace lifecycle commands, and distributable packaging.
